# 2026-07-23 工作日志

## DX12 交替黑帧故障诊断

完成 DX12 渲染管线全面审查与根因分析，定位"正常帧+黑帧严格交替"故障。

### 诊断结论
- **根因1（最高概率）**: `FrameFenceValues[FRAME_COUNT]` 初始化为 `{0,0}`，与 fence 起始值 0 相同，导致第一帧周期中 MoveToNextFrame 的保护等待被跳过。形成持续的 cycle 级交替黑帧。
- **根因2（高概率）**: `Present(1,0)` 只等 VSync 不等 GPU 完成，144Hz 下 VBlank 间隔 6.94ms，GPU 渲染超过该时限时 DWM 取到未完成的 buffer。
- **根因3**: Back buffer RTV 描述符句柄可能错位指向同一物理 buffer。
- 其他次要根因：CPU/GPU 状态追踪不同步、COPY_DEST 状态警告级联错误。

### 建议修复
1. **P0**: 在 `CreateFence()` 后主动 signal+wait fence 到值 1，然后初始化 `FrameFenceValues` 为该值
2. **P0**: 在 `EndFrame()` 的 `Present()` 前添加 `Fence->Signal()` + `Fence->Wait()` 确保 GPU 完成
3. P1: FRAME_COUNT 改为 3（三缓冲）

### 审查范围
- 交换链: FLIP_DISCARD, 双缓冲, VSync=1, AlphaMode=IGNORE
- 帧管理: 单命令列表 + 2个分配器轮换, DX12Fence 封装
- 渲染流程: BeginFrame → BeginImGuiFrame → BeginSceneRender → EndSceneRender → EndImGuiFrame → EndFrame
- 状态管理: RenderTargetDX12/DepthStencilDX12 各自维护 CPU 端 CurrentState
- Resize: ExecuteResize 正确释放并重建 pRenderTargets

### 第二轮诊断结果（关键发现）
1. **EMPTY DRAW DATA 是误报**：诊断代码在 ImGui::Render() 前读取 GetDrawData()，拿到旧数据。已修正。
2. **根因确认**: 所有 D3D12 错误指向同一资源地址 = 场景渲染目标（SceneRT）
   - ClearRenderTargetView 失败：SceneRT 在 PIXEL_SHADER_RESOURCE 状态
   - ResourceBarrier 警告��CPU 说 PIXEL_SHADER_RESOURCE，GPU 说 RENDER_TARGET "(assumed at first use)"
   - DrawIndexedInstanced ×8 失败：SceneRT 在 PIXEL_SHADER_RESOURCE，期望 RENDER_TARGET
3. **根因机制**: `TransitionTo()` 中 `if (CurrentState == newState) return;` 的 no-op 优化导致 CPU/GPU 状态追踪不一致时跳过了必要的 barrier。D3D12 调试层的 GPU-Based Validation 与 CPU 端追踪在某些跨命令列表边界场景下不同步。

### 第三轮修复（已实施）
- **RenderTargetDX12.cpp TransitionTo()**: 移除 `if (CurrentState == newState) return;`，始终发出 barrier
- **DepthStencilDX12.cpp TransitionTo()**: 同样移除早期返回，始终发出 barrier
